# Set up Endform in CI

1. If the repository already had Playwright tests, do not run them locally; their first CI run checks them. Tests you just wrote are the exception: run them once as the setup step describes. The `test`, `connect`, and `api-key` commands need a login. Do not log in up front. Only if one of them says you are not logged in, run `npx endform@latest login`, show the URL it prints, follow its output until the login completes, then run the command again.
2. Find which CI system this repository uses from its config, such as `.github/workflows`, `.gitlab-ci.yml`, `.circleci`, `azure-pipelines.yml`, or `bitbucket-pipelines.yml`. If there is none, ask which one to use.
3. Decide what the tests run against in CI. Pick the option the repository clearly uses. If more than one fits, for example a `webServer` in an app that deploys to Vercel, ask which one to use.
   - A local server started in CI through `webServer`: no `BASE_URL` needed.
   - A remote server such as staging: set `BASE_URL` in the CI config to its URL, and ask for it if it is not in the repo.
   - The Vercel preview of each pull request, on GitHub Actions only: follow [vercel.md](vercel.md) instead of the remaining steps, or the Vercel section of https://endform.dev/docs/_llms-txt/github-actions-ci-and-vercel.txt.
   - The Netlify Deploy Preview of each pull request: the Endform Netlify extension runs the tests, so follow [netlify.md](netlify.md) instead of the remaining steps and add no CI job.
4. Keep the triggers of a CI config that already runs Playwright. If it runs on only pull requests or only pushes to the default branch, say so in your summary. A new CI config runs on both pull requests and pushes to the default branch.
5. If it is GitHub Actions:
   - After the other changes, ask which authentication to use, and recommend the GitHub App. The Endform GitHub App needs no secret and is required for Vercel previews, but someone has to be able to install GitHub Apps on the repository. An API key is stored as the `ENDFORM_API_KEY` secret; with it, Vercel previews are not available, so the tests run against a staging URL instead.
   - If a workflow already runs `playwright test`, directly or through a package script such as `pnpm test:e2e`, replace that command in the CI config with `npx endform@latest test` and leave the package script as it is, so local runs keep using Playwright. Keep the other steps, and drop what Endform replaces: browser installs and caches, `--shard` matrix jobs, and the job that merges their blob reports. Endform runs the whole suite in parallel in one job. Create `.github/workflows/endform-e2e.yml` as shown in https://endform.dev/docs/_llms-txt/github-actions-ci-and-vercel.txt only if no workflow runs Playwright; read it only for this step. With the GitHub App, authentication uses OIDC: add `id-token: write` to the workflow's permissions and keep `contents: read`, since listing any permission removes the ones not listed. With an API key, set `ENDFORM_API_KEY: ${{ secrets.ENDFORM_API_KEY }}` in the job's environment.
   - With the GitHub App, connect it with `npx endform@latest connect github --organization-id <organization-id>`. It prints a URL where the install is finished in the browser and tells you which command to run next, so show the URL and follow its output until it is connected.
   - With an API key, create it with `npx endform@latest api-key create --name "GitHub Actions" --organization-id <organization-id> | gh secret set ENDFORM_API_KEY` so the key is never shown. If the command fails, no key was stored, so fix the error and run it again. Reference the secret, never write its value.
6. For any other CI system:
   - If a job already runs `playwright test`, directly or through a package script such as `pnpm test:e2e`, replace that command in the CI config with `npx endform@latest test` and leave the package script as it is, so local runs keep using Playwright. Keep the other steps, and drop what Endform replaces: browser installs and caches, `--shard` parallel jobs, and the job that merges their blob reports. Endform runs the whole suite in parallel in one job. Otherwise add a job that installs dependencies and runs `npx endform@latest test`. Examples for GitLab CI, CircleCI, Azure Pipelines, and Bitbucket Pipelines are in https://endform.dev/docs/_llms-txt/github-actions-ci-and-vercel.txt; read it only for this step.
   - Authentication uses the `ENDFORM_API_KEY` variable; reference it, never write its value. Create the key with `npx endform@latest api-key create --name "<CI system name>" --organization-id <organization-id>`, which prints only the key. If the CI system's CLI is installed and logged in, pipe the key straight into it to set the variable without showing the key, for example `npx endform@latest api-key create --name "GitLab CI" --organization-id <organization-id> | glab variable set ENDFORM_API_KEY --masked` for GitLab CI. If the command fails, no key was stored, so fix the error and run it again. Otherwise stop and give the command to run and the variable to add.
7. If the tests read other environment variables, such as app credentials, list them and ask for them to be added as CI secrets. Reference them in the job, never write their values.
